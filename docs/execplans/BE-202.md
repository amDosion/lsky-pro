# BE-202 ExecPlan

## Goal

把 AI 检索和 Prompt V2 的读侧消费从控制器 SQL 与 `AiPromptService` 内联 metadata 构造中拆出来，优先消费 `intelligenceRecord`，保留 legacy fallback。

## Status

已完成并通过当前可运行验证。

## Scope

- 新增 `App\Services\AiSearchService`
- 新增 `App\Services\ImageIntelligence\ImagePromptContextBuilder`
- 薄改：
  - `app/Http/Controllers/Api/V1/ImageController.php`
  - `app/Services/AiPromptService.php`
  - `app/Http/Controllers/Api/V1/AiController.php`
  - `app/Jobs/GenerateAiPromptTaskJob.php`
- 新增或修改相关 feature tests

## Constraints

- 不改 migration
- 不改 `ImageService`
- 不改 auth 页面与 admin settings
- 接口 shape 尽量兼容

## Implementation

- `ImageController::aiSearch()` 已保持接口 shape 不变，查询逻辑下沉到 `AiSearchService`
- `AiSearchService` 现在优先命中 `image_intelligence_records` 的 `caption/summary/prompt_hint/labels/keywords/ocr_text`，并保留 `images.ocr_text` 与标签表的 legacy fallback
- `ImagePromptContextBuilder` 现在分层构建：
  - legacy 基础上下文：文件名、尺寸、标签、OCR、派生 caption/summary/prompt_hint
  - intelligence 覆盖层：优先使用 record 中的 `labels/keywords/caption/summary/prompt_hint/ocr_text/status/source`
  - 当 intelligence 字段为空时，逐字段回退到 legacy 上下文
- `AiPromptService` 保持对外结果结构兼容，继续输出 `prompt/metadata/template_used/provider/language/style`
- `AiController` 与 `GenerateAiPromptTaskJob` 显式预加载 `intelligenceRecord`，避免 Prompt V2 读侧退化回 legacy-only 查询
