# Lsky-Pro 存储策略创建页深度优化方案

## 1. 核心问题诊断
* **页面跳动严重**：不同存储驱动字段差异巨大，切换驱动时页面无过渡跳动，体验极差。
* **盲填风险高**：缺乏“测试连接”功能，管理员需保存后才知道配置是否生效，调试成本高。
* **信息层级混乱**：敏感信息（Key/Pass）与常规信息（URL/Path）混杂，缺乏逻辑分组。
* **引导不专业**：纯文字警告散乱，缺乏可视化引导（如驱动 Logo、智能填充等）。

---

## 2. 优化原则
1. **可视化优先**：使用品牌图标选择驱动，增强识别度。
2. **逻辑分块**：将表单拆分为【凭证】、【节点】、【访问】三个逻辑区域。
3. **闭环验证**：增加“测试连接”功能，确保配置即填即验。
4. **安全与便捷并重**：增加敏感信息显隐切换。

---

## 3. 模块化设计方案

### A. 驱动可视化选择器 (顶部)
* **重构**：用水平滚动的图标卡片代替 `key` 下拉框。
* **效果**：高亮选中的驱动，动态加载对应的表单 Fragment。

### B. 配置项分组布局
* **[Section 1] 身份认证**：包含 Key、Token、密码等，支持明文/密文切换。
* **[Section 2] 连接与节点**：包含 Endpoint, Region, Bucket，增加常见节点的自动填充。
* **[Section 3] 访问预设**：包含访问域名、根路径等，增加 URL 自动补全（补全协议头）。

### C. “测试连接”交互流
* **按钮设计**：位于提交按钮旁，点击后展示 Loading 状态。
* **反馈机制**：成功显示绿色 Check 标记；失败显示详细错误（如：S3 Error: InvalidAccessKeyId）。

---

## 4. 技术实施
1. **Fragment 化模版**：将各驱动的配置字段提取为独立的 Blade Partial，减少单文件复杂度。
2. **Ajax 连接测试**：封装统一的驱动测试接口，利用现有的 Storage 抽象层进行连接尝试。
3. **响应式增强**：使用 CSS `min-height` 减少由于字段数量不同导致的页面高度波动。
