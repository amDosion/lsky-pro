# Lsky-Pro 系统设置工作台深度优化方案

## 1. 核心问题诊断
* **信息密度过载**：所有配置项单页平铺，侧边导航仅作为锚点，导致页面极长，心理压力大。
* **反馈链路过时**：尤其是邮件配置，仍沿用“填写-保存-手动测试”的流程，缺乏即时验证能力。
* **开关项缺乏警示**：核心系统开关（注册、API等）隐藏在普通配置中，缺乏视觉权重和关联影响提示。
* **运维功能混杂**：系统升级属于高危运维操作，与“修改网站名称”等基础配置放在一起，缺乏仪式感和安全隔离。

---

## 2. 优化原则
1. **内容解耦**：从“长单页”转向“动态板块”，确保用户注意力集中。
2. **即时验证 (Live Validation)**：关键配置（如邮件、API 密钥）支持填完即测，无需先保存。
3. **分级警示**：对安全相关开关进行视觉强化，并增加风险评估。
4. **运维一体化**：将版本检查、环境体检与升级操作整合为独立的“健康中心”模块。

---

## 3. 模块化设计方案

### A. 智能导航系统
* **重构**：侧边栏支持固定布局，右侧内容区异步切换。
* **增强**：在侧边栏每个 Tab 旁边显示一个“状态点”（如：邮件未配置显示红点，升级可用显示蓝点）。

### B. 邮件/通知配置中心 (重塑交互)
* **智能填充**：内置主流 SMTP 服务商模板。
* **内嵌测试终端**：在配置页面直接显示测试发信的过程日志，方便排错。

### C. 系统开关概览 (Control Board)
* **可视化卡片**：使用 2x3 的网格展示核心开关。
* **依赖关系提示**：例如，关闭“注册”时，提示“当前已开启游客上传，新用户仍可匿名使用”。

### D. 系统升级与运维
* **仪表化**：用圆盘图表展示当前版本与最新版本的差异。
* **环境自检**：增加 PHP 扩展、目录权限、数据库版本的实时体检。

---

## 4. 技术实施
1. **Axios/Alpine 实现即时保存**：对非文本类开关引入 `change` 事件即时提交。
2. **Markdown 实时预览**：在“网站公告”编辑框旁增加同步预览区域。
3. **异步升级逻辑重写**：将升级进度查询从简单的 setInterval 优化为更健壮的状态轮询机制。
