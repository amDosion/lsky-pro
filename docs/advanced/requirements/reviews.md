# reviews 页面需求文档

## 目标
建设内容审核页面，支持机器预审与人工复审协同，形成“规则可配置、流程可追溯、结果可复核”的审核闭环，满足合规要求。

## 用户故事
- 作为审核员，我希望在单一页面处理待审队列并快速给出审核结论。
- 作为运营人员，我希望查看审核失败原因并进行申诉或重提。
- 作为管理员，我希望配置审核规则和策略阈值。
- 作为合规负责人，我希望导出审核日志用于监管抽检。

## 功能范围
### In Scope
- 审核队列：待审、已通过、已驳回、需复核。
- 审核动作：通过、驳回、打回重提、升级复核。
- 审核来源：自动规则命中、用户举报、人工抽检。
- 规则配置：关键词、OCR 命中、标签黑白名单、风险分阈值。
- 审核证据：命中规则详情、历史审核记录、附件说明。

### Out of Scope
- 外部司法系统对接。
- 自动法律条文解释。
- 视频帧级细粒度审核。

## 输入输出
### 输入
- 审核对象：资源 ID、风险分类、来源渠道。
- 审核参数：优先级、SLA、指派审核组。
- 审核结论：`approve/reject/needs_revision/escalate` + 原因码 + 备注。

### 输出
- 审核结果：最终状态、生效时间、执行人、复核链路。
- 通知结果：站内通知/邮件/Webhook 发送状态。
- 统计报表：审核量、通过率、驳回率、平均处理时长。

## 权限
- `review.read`：查看审核队列与详情。
- `review.execute`：执行审核动作。
- `review.override`：复核并覆盖原结论。
- `review.rule.manage`：管理审核规则。
- `review.export`：导出审核记录。
- 角色建议：
  - Super Admin/Admin：全权限。
  - Reviewer：`read/execute`，可选 `override`。
  - Operator：`read`。
  - Auditor：`read/export`。

## 异常处理
- 审核对象不存在：任务自动关闭并标记 `TARGET_NOT_FOUND`。
- 重复审核提交：基于版本号幂等校验，仅首个请求生效。
- 规则服务不可用：进入人工优先模式并触发告警。
- 通知发送失败：不影响审核主流程，支持异步补发。
- 越权复核：返回 `403` 并记录安全日志。

## 验收标准
- 审核员可在同一页面完成列表筛选、详情查看、结论提交。
- 审核结论提交后，资源状态在 3 秒内可见一致更新。
- 对同一审核对象的并发提交不会产生冲突状态。
- 所有审核动作均可追溯到操作者与原因码。
- 报表支持按日/周/月维度导出。

## 非功能要求
- 性能：审核列表接口 P95 < 1.2s。
- 可用性：审核核心链路可用性 >= 99.95%。
- 安全：审核备注支持敏感词审计与脱敏展示策略。
- 可靠性：通知系统故障不阻断审核状态落库。
- 合规：审核记录至少保留 365 天，支持检索。
