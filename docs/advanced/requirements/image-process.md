# image-process 页面需求文档

## 目标
构建统一的图像处理页面，支持批量处理、异步执行与结果追踪，实现压缩、格式转换、裁剪、加水印等能力，降低人工处理成本并提升素材交付效率。

## 用户故事
- 作为运营人员，我希望一次性选择多张图片并批量压缩，以便快速满足平台体积限制。
- 作为设计师，我希望对一组图片统一加品牌水印并导出，以保持视觉一致性。
- 作为管理员，我希望查看处理任务状态和失败原因，以便及时重试或修正参数。
- 作为审计员，我希望查看谁在何时发起了哪些处理任务，以满足审计要求。

## 功能范围
### In Scope
- 单图/批量任务创建。
- 处理动作：缩放、裁剪、旋转、格式转换（jpg/png/webp/avif）、质量压缩、水印叠加。
- 任务模式：立即执行、定时执行。
- 处理结果：文件级成功/失败明细、结果预览、批量下载。
- 任务管理：查看进度、取消任务、失败重试。

### Out of Scope
- 视频处理与音频处理。
- AI 图像生成。
- 跨租户共享处理任务。

## 输入输出
### 输入
- 资源选择：图片 ID 列表、来源目录、标签筛选条件。
- 处理参数：
  - 尺寸策略（固定宽高/按比例/最长边限制）
  - 输出格式与质量参数
  - 水印类型（文字/图片）、位置、透明度、边距
  - 文件命名规则（保留原名/前后缀/模板变量）
- 执行参数：优先级、并发级别、是否覆盖原图、定时时间。

### 输出
- 任务级输出：任务 ID、状态（pending/running/success/partial_failed/failed/cancelled）、创建时间、完成时间。
- 文件级输出：原图 ID、新图 ID（如生成）、处理耗时、失败错误码。
- 可下载结果：成功文件集合（zip）与失败报告（csv/json）。

## 权限
- `image.process.create`：创建处理任务。
- `image.process.manage`：取消、重试、批量操作任务。
- `image.process.read`：查看任务与结果。
- `image.process.export`：导出处理结果。
- 角色建议：
  - Super Admin/Admin：全权限。
  - Operator/Editor：`create/read/export`，可选 `manage`。
  - Auditor：仅 `read`。

## 异常处理
- 参数非法：返回字段级错误提示，阻止任务创建。
- 源文件缺失或无权限：跳过该文件并记录 `SOURCE_NOT_FOUND`/`SOURCE_FORBIDDEN`。
- 不支持的格式：记录 `FORMAT_UNSUPPORTED`，其他文件继续处理。
- 处理引擎超时：任务进入 `partial_failed`，支持按失败文件重试。
- 存储写入失败：记录 `STORAGE_WRITE_FAILED`，并回滚未完成元数据。
- 用户取消任务：未执行项终止，已完成项保留并可下载。

## 验收标准
- 可在页面创建包含至少 100 张图片的批量任务，任务创建接口在 P95 < 2s。
- 处理动作可组合执行，且执行顺序符合配置顺序。
- 失败文件必须在结果页可定位到明确错误码与错误描述。
- 取消任务后，不再继续消耗队列资源处理未开始文件。
- 审计日志可按任务 ID 检索到完整操作链路。

## 非功能要求
- 性能：单任务支持至少 10,000 张图片；并发处理可配置。
- 可靠性：任务状态落库必须幂等，避免重复消费导致重复产物。
- 安全：处理参数需做白名单校验，禁止任意路径写入。
- 可观测性：提供任务吞吐、失败率、平均耗时指标与告警。
- 可维护性：处理动作采用可扩展插件式注册机制。
