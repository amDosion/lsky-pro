# Lsky-Pro 账户设置页 (Settings 3.0) 深度优化方案

## 1. 核心问题诊断 (Pain Points)
* **黑盒术语堆砌**：`Legacy Snapshot`、`Foundation Ready`、`Auth Identities` 等术语直接暴露给用户，导致认知成本过高。
* **信息架构失衡**：页头的 Hero 区域占据过多空间但有效信息密度低；底部的“治理 (Governance)”部分展示了过多的原始审计数据。
* **交互逻辑割裂**：Google、GitHub 和 Passkey 的展示逻辑不统一，操作按钮的状态切换过于生硬。
* **调试痕迹严重**：界面中包含大量“后端已返回状态”、“镜像兼容说明”等用于开发排错的占位文案。

---

## 2. 优化原则 (Refactoring Principles)
1. **用户视角化 (User-Centric)**：将技术实现细节隐藏，只展示用户关心的“状态”和“操作”。
2. **统一化 (Uniformity)**：将不同类型的登录方式（密码、社交、Passkey）抽象为统一的“安全凭证”组件。
3. **结果导向 (Outcome-Driven)**：将复杂的“治理逻辑”转化为直观的“安全等级”和“优化建议”。

---

## 3. 模块化重构设计 (Modular Design)

### A. 头部概览：从“统计”转向“身份”
* **重构**：采用简洁的“左头像 + 右基本信息”布局。
* **安全分值**：将原有的 `Governance` 逻辑简化为一个“安全盾牌”图标，根据账户完整度显示绿色（优）、黄色（良）、红色（危）。

### B. 资料修改：表单精简化
* **合并**：将基本资料（UID、昵称、邮箱）与修改密码合并入一个清晰的“基础设置”卡片。
* **交互**：采用“行内编辑”或“点击展开修改”模式，避免长表单压迫感。

### C. 登录与安全：统一凭证管理
将密码、Google、GitHub 和 Passkey 合并入 **“登录方式 (Sign-in Methods)”** 卡片：
* **状态翻译**：
    * `Linked` -> “已关联：[Email]” (绿色勾选)
    * `Available` -> “未关联” (灰度图标)
    * `Blocked` -> “无法解除（必须保留一种登录方式）” (锁定图标)
* **Passkey (安全密钥)**：展示设备名称（如 "MacBook TouchID"），移除底层 challenge 等调试信息。

### D. 账户治理：从“流水”转向“建议”
* **隐藏**：默认隐藏 `governance-timeline`（事件流）和 `method_inventory`（原始清单）。
* **转化**：如果用户只绑定了密码，显示黄色建议：“建议关联社交账号或开启 Passkey，防止遗忘密码导致失联”。

---

## 4. 技术执行路径 (Technical Roadmap)
1. **第一阶段：文案清洗**：建立 `ui_map` 对象，将后端返回的 code 映射为友好的中文。
2. **第二阶段：结构重构**：将登录方式渲染逻辑抽象为统一的组件。
3. **第三阶段：加载状态优化**：增加 Skeleton (骨架屏) 效果，移除“读取中”等生硬文字。
