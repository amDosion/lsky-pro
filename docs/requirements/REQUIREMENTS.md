# Lsky Pro 加固与可扩展性需求文档

## 背景
当前系统可用，但存在同步上传链路过重、可观测不足、安全基线不一致、扩展能力受限等问题。项目目标是在保持 API v1 兼容的前提下，完成安全、性能、可靠性与运维能力升级。

## Goals
1. 建立生产安全基线（鉴权、输入校验、审计、依赖治理）。
2. 上传链路从同步重处理演进为“同步最小闭环 + 异步后处理”。
3. 建立可量化性能指标并达标。
4. 建立可用性与恢复指标（RTO/RPO）并通过演练。
5. 完成可持续运维（监控、告警、SOP、容量规划）。

## Non-goals
1. 不重做前端框架与 UI。
2. 不引入新业务域（计费/工单等）。
3. 不废弃 API v1。
4. 不做大版本框架迁移。

## Scope
### In Scope
- 上传链路安全与性能改造
- Sanctum token 生命周期与权限收敛
- 限流防刷
- 存储策略可靠性增强
- 数据库与缓存优化
- 可观测性与运维手册

### Out of Scope
- 第三方云厂商 SLA 治理
- 图片之外文件类型完整产品化

## 功能需求（摘要）
- FR-01：生产安全配置自检与阻断（如生产禁用 `APP_DEBUG=true`）。
- FR-02：Token 生命周期、主动吊销、scope 能力。
- FR-03：管理操作审计日志（操作者/IP/对象/结果）。
- FR-04：上传输入三重校验（扩展名+MIME+文件头）。
- FR-05：统一限流（登录/发 token/上传/管理）。
- FR-06：审核/水印/缩略图异步化与任务状态机。
- FR-07：存储失败重试、可选降级。
- FR-08：热点索引优化与迁移脚本。
- FR-09：统一 trace_id 与核心指标面板。
- FR-10：灰度开关与回滚开关。

## 非功能需求
### Security
- CORS 白名单，禁止 `*` 上生产。
- 密钥不入库不入日志。
- 高危漏洞清零后发布。

### Performance
- 上传 API（1MB 图）: P95 <= 800ms, P99 <= 1500ms（不含异步后处理）。
- 读图: 命中缓存 P95 <= 300ms，未命中 P95 <= 900ms。

### Reliability
- 月可用性 >= 99.95%
- 上传成功率 >= 99.9%
- RTO <= 30 分钟，RPO <= 5 分钟

## 里程碑
- M0：基线评估与方案冻结
- M1：安全加固一期
- M2：扩展性改造一期（异步/索引/队列）
- M3：可靠性与灾备演练
- M4：灰度到全量与稳定运行

## 验收
- 安全：无可复现高危漏洞
- 性能：压测达标并有对比报告
- 可靠性：故障演练达标
- 回归：API v1 兼容回归 100% 通过
